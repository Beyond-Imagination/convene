# STT 벤치 하네스

설정 변경이 실제로 품질을 올렸는지, 그 대가로 얼마를 쓰는지 재는 도구.
`CER · RTF · 피크 RSS` 세 지표를 항상 같이 낸다 — Lightsail 2GB / 2 vCPU 라 품질만
보고 고르면 배포가 안 된다.

## 샘플 준비

오디오와 정답 전사를 **같은 이름으로** 나란히 둔다. 화자별 하위 폴더까지 훑으므로
덤프된 자리에서 바로 채우면 된다. 비어 있는 `.txt` 는 자동으로 건너뛴다.

```
samples/raw/
├── {화자A}/1786457659-0002.wav
├── {화자A}/1786457659-0002.txt   # 사람이 받아쓴 정답 전사
└── INDEX.md                      # 파일·길이 체크리스트
```

`prev-` 로 시작하는 폴더는 과거 수집분 보관용이라 벤치에서 제외된다.

오디오는 git 에 커밋하지 않는다(`.gitignore` 처리됨).
실제 회의 녹음이라 개인정보가 들어 있고, 이미지에도 넣을 이유가 없다.

### 오디오는 파이프라인에서 떠낸다

운영 오디오는 `opus 인코딩 → 네트워크 손실 → ffmpeg 디코딩 → agate 게이트 → 16kHz` 를 거치는데,
STT 품질을 떨어뜨리는 게 정확히 이 경로다. 이걸 안 거친 깨끗한 오디오로 튜닝하면 실제로는 안 통하는 설정을 고르게 된다.

`STT_DUMP_DIR` 을 켜고 로컬 회의를 하면 ai-worker 가 받은 wav 를 그대로 떨군다 — 모델이 보는 것과 바이트 단위로 동일하다.

`docker-compose.local.yml` 에 배선은 돼 있고, 환경 변수만 채우면 켜진다.
**필터를 끈 채로 뜬다** — 필터를 거친 오디오에는 후보 체인을 다시 걸 수 없어서,
필터 전 오디오를 확보해야 녹음 한 번으로 모든 단계를 평가할 수 있다.

```bash
STT_DUMP_DIR=/app/bench/samples/raw \
FFMPEG_AUDIO_FILTER=none \
docker compose -f docker-compose.local.yml up
```

로컬에서 회의를 하고 나면 `samples/raw/` 에 30초 내외 wav 가 쌓인다(참가자별로 분리돼 있다).
쓸 만한 것을 골라 `samples/` 로 옮기고 같은 이름의 `.txt` 를 받아쓴다.
수집이 끝나면 두 변수를 빼고 다시 띄운다 — 켜 둔 채로 두면 계속 쌓인다.

현행 필터를 거친 버전이 필요하면 오프라인으로 만든다(재녹음 불필요).

```bash
ffmpeg -i samples/standup-01.wav \
  -af "agate=threshold=-45dB:range=0.01:release=1000" \
  samples/standup-01-agate.wav
```

> `STT_DUMP_DIR` 은 **로컬 전용**이다. `docker-compose.prod.yml` 은 이 변수를 넘기지
> 않으며, 넘겨서도 안 된다 — 오디오는 전사 후 즉시 폐기가 원칙이다.

### 정답 전사 작성 규칙

**형식은 그냥 평문이다.** 한 줄로 쭉 써도 되고 여러 줄로 나눠도 된다 — 하네스가 공백·줄바꿈을
하나로 합치므로 결과가 같다. 화자 표기나 타임스탬프는 넣지 않는다(파일 하나가 곧 한 화자다).

하네스가 문장부호·대소문자·중복 공백을 정규화하므로 거기엔 신경 쓰지 않아도 된다. 대신 아래는 지킨다.

- **영어 기술 용어는 원하는 출력 형태로 적는다** — `API`(O) / `에이피아이`(X). hotwords 평가의 정답이 바로 이 표기다.
- **의미 없는 filler(어, 음, 그)는 뺀다.** Whisper 는 이걸 떨구도록 학습돼 있어, 정답에 넣으면 정상 출력이 오류로 잡힌다.
- **실제로 발화한 단어는 전부 넣는다.** 말끝 흐림·반복도 발화했으면 적는다.
- 숫자는 발화한 대로 — "삼십 분"이라 말했으면 `삼십 분`, "30분"이라 말했으면 `30분`.

### 어떤 오디오를 모아야 하는가

- **한 파일에 한 명.** 파이프라인이 이미 참가자별로 분리돼 있어(참가자당 ffmpeg 1개, redis 버퍼 분리) 모델은 섞인 오디오를 볼 일이 없다. 단일 화자가 정확한 형태다.
- **읽지 말고 대화한다.** 낭독은 STT 에 훨씬 쉬워서 개선 효과가 과대평가된다.
- **기술 용어를 실제로 섞는다.** hotwords 의 평가 대상이다.
- **화자 2명 이상.** 목소리·마이크가 달라야 04단계(마이크 편차 정규화)를 판정할 수 있다.
- 총 5~10분이면 시작하기 충분하다.

## 실행

faster-whisper 가 설치된 곳에서 돌린다(= ai-worker 컨테이너 안).

`bench/` 는 compose 에서 이미 마운트되므로 이미지 재빌드 없이 반복 실행된다.

```bash
docker compose -f docker-compose.local.yml run --rm \
  ai-worker python bench/run_bench.py --configs bench/configs.mine.json --out bench/result.json
```

비교할 설정은 매번 직접 쓴다. 지난 sweep 정의는 그때의 가설에만 맞아서 커밋하지 않는다
(`configs.*.json` · `result*.json` 은 ignore 대상).

```json
[
  {
    "name": "baseline",
    "model": { "size": "small", "compute_type": "int8", "cpu_threads": 2 },
    "decode": { "language": "ko", "beam_size": 1, "vad_filter": true, "condition_on_previous_text": false }
  }
]
```

`model` 은 `WhisperModel()` 로(`size` 만 빼서 첫 인자로), `decode` 는 `transcribe()` 로 그대로
넘어간다. 새 파라미터를 시험할 때 하네스 코드를 고칠 필요가 없다.

## 지표 읽는 법

| 지표         | 의미              | 판단 기준                                        |
|------------|-----------------|----------------------------------------------|
| **CER**    | 문자 오류율. 띄어쓰기 제외 | **주 지표.** 낮을수록 좋다                            |
| WER        | 어절 오류율          | 참고용. 한국어는 띄어쓰기 차이에 과민해 과대평가된다                |
| **RTF**    | 오디오 1초당 처리 초    | **동시 발화 참가자 수를 곱한 값이 1.0 을 넘으면 실시간 처리가 밀린다** |
| **피크 RSS** | 프로세스 최대 메모리     | ai-worker 예산은 약 900MB. `mem_limit` 보다 낮아야 한다 |

CER 은 샘플별 평균이 아니라 `편집거리 합 / 전체 길이 합`(micro average)이다.
짧은 샘플이 과대 대표되지 않는다.

설정마다 자식 프로세스를 새로 띄운다 — `ru_maxrss` 가 프로세스 생애 최대값이라 한 프로세스에서 연속 측정하면 앞 설정의 피크가 뒤에 그대로 남기 때문이다.
